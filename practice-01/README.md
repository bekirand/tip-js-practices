### Задание 5. Поиск логических ошибок через DevTools (`debug.js`)

Исходный файл содержал две намеренные ошибки:
1. `completedTotal = completedText + additionalText` давало строковую конкатенацию `"3"` + `"2"` = `"32"` вместо числа `5`.
2. Условие цикла `taskNumber < 4` останавливало суммирование на числе 3 (сумма $1 + 2 + 3 = 6$ вместо $1 + 2 + 3 + 4 = 10$).

**Таблица анализа отладки:**

| Ошибка | Что наблюдалось до исправления | Первопричина | Способ исправления | Результат после исправления |
|:---|:---|:---|:---|:---|
| Расчет выполненных задач | `Выполнено: 32`, `Осталось: -24` | Конкатенация строк `"3" + "2"` | Явное приведение `Number(completedText) + Number(additionalText)` | `Выполнено: 5`, `Осталось: 3` |
| Граница цикла контрольной суммы | `Контрольная сумма: 6` | Строгое неравенство `< 4` исключило 4 | Замена условия на `<= 4` (`taskNumber <= 4`) | `Контрольная сумма: 10` |

**Итоговый вывод исправленного файла:**
```text

Осталось: 3
```

### Дополнительное задание (Вариант А). Обработка строковых входных данных (`progress-input.js`)

Реализована защитная функция `validateAndParse`, которая выполняет:
1. Проверку типа: значение обязательно должно быть строкой (`typeof input === "string"`).
2. Удаление краевых пробелов методом `.trim()`.
3. Отклонение пустых строк и строк, состоящих только из пробелов.
4. Явное приведение через `Number(trimmed)` с последующей проверкой на конечность (`Number.isFinite`) и целочисленность (`Number.isInteger`).

**Таблица проверок строкового ввода:**

| Входные строки | Ожидание | Фактический результат | Итог |
|:---|:---|:---|:---:|
| `total = " 9 "`, `comp = "9"` | Успешный расчет для варианта 3 | 9 задач, 100.0%, Завершено | **Пройдено** |
| `""` (пустая строка) | Ошибка: пустая строка | Ошибка: totalTasks не должен быть пустой строкой | **Пройдено** |
| `"   "` (пробелы) | Ошибка: пустая строка после trim | Ошибка: totalTasks не должен быть пустой строкой | **Пройдено** |
| `"abc"` | Ошибка: недопустимое число | Ошибка: totalTasks содержит недопустимое число (NaN или Infinity) | **Пройдено** |
| `"2.5"` | Ошибка: дробное число | Ошибка: totalTasks должен быть целым числом | **Пройдено** |
| `"Infinity"` | Ошибка: бесконечность | Ошибка: totalTasks содержит недопустимое число (NaN или Infinity) | **Пройдено** |
| `null` | Ошибка: не строка | Ошибка: totalTasks должен быть строкой | **Пройдено** |
| `undefined` | Ошибка: не строка | Ошибка: totalTasks должен быть строкой | **Пройдено** |

**Ответ на контрольный вопрос задания:**  
Почему недостаточно просто вызвать `Number(input) >= 0`?
1. `Number("")` и `Number("   ")` в JavaScript возвращают `0`, что дало бы ложное положительное срабатывание `0 >= 0`.
2. `Number(null)` также возвращает `0`.
3. `Number("2.5")` дает `2.5 >= 0` (дробное количество задач).
4. `Number("Infinity")` дает `Infinity >= 0`.  
Следовательно, требуется строгая многоступенчатая валидация: проверка строкового типа, очистка пробелов через `trim()`, проверка на непустую строку и методы `Number.isFinite()` и `Number.isInteger()`.
