## Цель и результат

Реализован собственный HTTP-сервер на Node.js и Express 5.1.0, выполняющий операции чтения задач и категорий с поддержкой фильтрации, валидации параметров и единого формата ошибок (400, 404, 405, 500), а также методов HEAD и OPTIONS с заголовками CORS.

## Установка и запуск

Команды выполняются из папки `practice-09`:

```bash
npm ci
npm start
```

API: `http://127.0.0.1:5505/api`. Проверка окружения: `/api/health`.

## Реализация

* **Разделение модулей:**
  * `validation.js` — разбор и проверка параметров пути (`parsePositiveId`) и строки запроса (`parseFilters`).
  * `task-service.js` — чистые функции выборки и поиска (`selectTasks`, `findTask`) без изменения исходного массива.
  * `store.js` — изолированное хранилище копий данных для экземпляра приложения.
  * `routes.js` — Express Router с обработчиками GET и заглушками 405 для изменяющих методов.
  * `app.js` / `server.js` — сборка middleware (CORS, OPTIONS, роутер, 404, errorHandler) и запуск HTTP-порта.
* **Нормализация `'false'` и контроль дубликатов:** `parseFilters` принимает `URLSearchParams`, проверяет повторное вхождение любого ключа через `Set` на `searchParams.keys()`, а параметр `completed` проверяется строго как строка `'true'` или `'false'` (чтобы избежать преобразования `Boolean('false') === true`).
* **Проверка `id`:** регулярное выражение `/^[1-9]\d*$/` вместе с `Number.isSafeInteger()` отсеивает ведущие нули, пробелы, дроби и хвосты наподобие `'4abc'`.
* **Порядок middleware:** заголовки и OPTIONS → GET-маршруты → `router.all` (405) → 404 для неизвестных путей → `errorHandler(error, req, res, next)`.

## Контракт

* **Маршруты:** `GET /api/health`, `GET /api/categories`, `GET /api/tasks`, `GET /api/tasks/:id` (а также HEAD и OPTIONS). Изменяющие методы возвращают 405 `METHOD_NOT_ALLOWED` и `Allow: GET, HEAD, OPTIONS` — реализация операций записи (POST, PATCH, DELETE) относится к ПР10.
* `meta.total` отражает размер **полученной выборки** с учётом применённых фильтров.

Пример ответа 200 (`/api/tasks/4`):
```json
{ "data": { "id": 4, "title": "Подготовить модель задач", "completed": false, "priority": "high", "categoryId": 2 } }
```

Пример ошибки 400 (`/api/tasks?priority=urgent`):
```json
{ "error": { "code": "INVALID_QUERY", "message": "Параметр priority должен быть low, medium или high." } }
```

## Исправленный дефект

* **Симптом:** Модульный тест «Логика работает с другим массивом» завершился ошибкой `ERR_ASSERTION: Values have same structure but are not reference-equal`.
* **Причина:** В первой версии `findTask` и `selectTasks` делали поверхностное копирование каждого объекта через `.map(t => ({ ...t }))`, тогда как тест `assert.equal(findTask(data, 101), data[0])` ожидает исходную ссылку объекта из переданного массива (а изоляцию данных обеспечивает `createStore` при инициализации).
* **Исправление:** `findTask` возвращает найденный элемент напрямую, `selectTasks` использует `tasks.filter(...)` и `[...tasks]` без пересоздания объектов.
* **Повторная проверка:** `npm test` — 90/90 пройдены успешно.

## Контрольные вопросы

1. *Чем Node.js отличается от браузера?* — Node.js выполняется вне браузера, не имеет DOM, `window` и `localStorage`, но предоставляет доступ к сети, файловой системе и процессу ОС.
2. *Что определяет выбор маршрута?* — HTTP-метод и путь URL (без query-строки).
3. *Чем `req.params` отличается от query?* — `req.params` — часть пути ресурса (например `/tasks/:id`), а query — необязательные параметры фильтрации/поиска после `?`.
4. *Почему `'false'` требует явного преобразования?* — В JS непустая строка `'false'` в булевом контексте даёт `true`.
5. *Зачем проверять весь `id` и `Number.isSafeInteger`?* — Чтобы отсечь хвосты (`'4abc'`), ведущие нули и числа больше `MAX_SAFE_INTEGER`.
6. *Почему пустая выборка — 200, а отсутствующая задача — 404?* — Сама коллекция `/tasks` существует (она просто пуста по фильтру), а конкретный ресурс `/tasks/2` не существует.
7. *В чём разница `TASK_NOT_FOUND` и `ROUTE_NOT_FOUND`?* — Первый означает отсутствие записи по корректному id на известном маршруте, второй — неизвестный URL.
8. *Чем 405 отличается от 404 и зачем `Allow`?* — 405 сообщает, что путь существует, но HTTP-метод запрещён; заголовок `Allow` перечисляет допустимые методы.
9. *Что означает `meta.total` при фильтрах?* — Количество записей, попавших в текущую отфильтрованную выборку.
10. *Как порядок middleware влияет на результат?* — Обработчики выполняются сверху вниз: если 404 стоит раньше маршрутов, до маршрутов управление не дойдёт.
11. *Почему обработчик ошибок имеет 4 параметра?* — Express распознаёт middleware ошибок именно по сигнатуре из 4 аргументов `(error, req, res, next)`.
12. *Зачем фабрика `createApp` отделена от запуска порта?* — Чтобы модульные HTTP-тесты могли создавать независимые экземпляры сервера на случайном свободном порту.
13. *Какие данные допустимо отправлять при 500?* — Только общее сообщение и код `INTERNAL_ERROR` без стека вызовов и внутренних деталей.
14. *Почему CORS не является авторизацией?* — Это политика браузера для чтения ответа JS-кодом; прямые HTTP-клиенты вроде `curl` CORS не проверяют.
15. *Какие изменения потребуются в ПР10?* — Подключить парсер JSON-тела, валидацию входного черновика, методы создания/обновления/удаления в `store` и маршруты `POST`, `PATCH`, `DELETE`.
