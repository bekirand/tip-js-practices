## Результат

Реализовано React-приложение для управления задачами (CRUD, фильтрация по статусу, поиску, приоритету и категории, валидация формы, сводная статистика). Данные хранятся в памяти страницы в состоянии `useState`, поэтому при перезагрузке страницы восстанавливается исходный набор из `src/data.js` — это ожидаемое поведение ПР7, отделяющее работу с React-компонентами от интеграции с внешним API (перенесено в ПР8).

## Компоненты и состояние

* **Владельцы состояний:**
  * `App.jsx` владеет общим состоянием списка `tasks`, текущими фильтрами `filters`, идентификатором редактируемой задачи `editingId`, а также статусными сообщениями.
  * `TaskForm.jsx` владеет локальным черновиком `draft` и объектом ошибок валидации `errors`.
* **Передача данных и обратные вызовы:** Данные передаются сверху вниз через props (`tasks`, `categories`, `filters`, `stats`). Действия пользователя поднимаются наверх через callback-функции (`onToggle`, `onEdit`, `onDelete`, `onSave`, `onCancel`, `onChange`).
* **Производные данные:** Отфильтрованный список `visibleTasks = selectTasks(tasks, filters)`, сводка `stats = getTaskStats(tasks)` и редактируемая задача `editingTask` вычисляются прямо во время рендера без дублирования в отдельном `useState`.
* **Неизменяемые обновления и сброс формы:** Все функции в `src/domain/task-service.js` возвращают новые массивы и новые объекты (через `map`, `filter`, спред-оператор). Переключение между созданием и редактированием разных задач выполняется через ключ `<TaskForm key={editingId ?? 'new'} ... />`, что заставляет React пересоздавать компонент с актуальным начальным состоянием.

## Контрольные вопросы

1. *Чем JSX отличается от строки HTML?* — JSX является синтаксическим расширением JavaScript и при сборке компилируется в вызовы создания виртуальных DOM-элементов, а не в сырую HTML-строку.
2. *Чем props отличаются от состояния?* — `props` передаются из родительского компонента и доступны только для чтения, а `state` принадлежит самому компоненту и может изменяться.
3. *Почему изменение обычной переменной не заменяет `useState`?* — Изменение локальной переменной не уведомляет React о необходимости повторного рендера и сбрасывается при следующем вызове функции.
4. *Когда требуется функциональная форма обновления состояния?* — Когда новое состояние вычисляется на основе предыдущего (`setTasks(prev => ...)`), чтобы исключить потерю данных при батчинге обновлений.
5. *Почему нельзя менять объект задачи внутри поверхностной копии массива?* — Поверхностная копия копирует ссылки на те же объекты задач; мутация объекта испортит исходные данные и не будет замечена при сравнении ссылок.
6. *Для чего списку стабильный `key` и почему индекс не подходит?* — `key` связывает DOM-элемент и внутреннее состояние с конкретной записью при перестановке, фильтрации и удалении; индекс привязан к позиции, а не к задаче.
7. *Почему видимая выборка и статистика не хранятся в отдельных состояниях?* — Они однозначно вычисляются из `tasks` и `filters`; хранение копий потребовало бы ручной синхронизации после каждого действия.
8. *Как дочерний компонент сообщает родителю о действии?* — Вызывает функцию-обработчик, переданную родителем через `props` (например, `onToggle(task.id)`).
9. *Что делает поле управляемым?* — Передача значения из состояния через `value` (или `checked`) и его обновление через обработчик `onChange`.
10. *Почему `categoryId` из `select` требует преобразования?* — Значение HTML-элемента `<select>` всегда строка, тогда как в модели данных `id` категории является числом.
11. *Как меняется состояние формы при изменении её ключа?* — React размонтирует старый экземпляр компонента и монтирует новый с начальным состоянием из текущих `props`.
12. *Почему подтверждение удаления не помещается внутрь функции обновления?* — В `StrictMode` функция обновления вызывается дважды для проверки чистоты, что привело бы к повторному открытию диалога `confirm`.
13. *Как отличить отсутствие задач от отсутствия совпадений фильтра?* — Сравнить длину общего массива `tasks` (или `stats.total`) и длину отфильтрованного `visibleTasks`.
14. *Что проверяет `npm test` и чего не проверяет?* — Проверяет чистые предметные функции из `task-service.js`, но не запускает браузер, JSX-рендер и пользовательские события.
15. *Какие части приложения потребуется изменить для подключения API в ПР8?* — Заменить синхронные обновления `tasks` на асинхронные запросы через HTTP-клиент, добавить загрузку данных через `useEffect` (кастомный хук) и состояния загрузки/ошибки.
