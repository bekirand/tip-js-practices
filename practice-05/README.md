Рабочая папка: `practice-05` внутри личного репозитория.

Проверка готового API:

```bash
npm run check:api
```

Полный набор после реализации клиента:

```bash
npm test
```

Для ручного сценария необходимы два терминала.

Терминал 1:


Терминал 2:

```bash
npm run example:fetch

```

Адрес API по умолчанию:

```text
http://127.0.0.1:5505/api
```

## Эксперимент с очередями выполнения

| Этап | Порядок меток | Объяснение |
|---|---|---|
| Прогноз до запуска | A, F, C, E, B, D | Синхронный код (A, F), затем микрозадачи Promise (C, E), затем макрозадачи таймера (B, D) |
| Фактический результат | A, F, C, E, B, D | Полностью совпало с прогнозом модели Event Loop |

- Синхронный код выполняется немедленно в текущем стеке вызовов (A, затем F).
- Микрозадачи `Promise.then` помещаются в очередь microtask queue и выполняются сразу после завершения текущего синхронного стека до макрозадач (C, затем E).
- Макрозадачи `setTimeout` (даже с задержкой 0) помещаются в macrotask queue и планируются на следующий тик цикла событий (B, затем D).

|---|---|---|

## Организация кода

| Файл | Ответственность |
|---|---|
| `api/server.mjs` | Локальный HTTP-сервер на чистом Node.js (без фреймворков), реализующий REST API для задач и категорий. |
| `src/api-client.js` | Транспортный клиент HTTP: формирование URL (`buildUrl`), отправка запроса через `fetch`, таймауты (`AbortSignal`), классификация ошибок в `ApiError`. |
| `src/task-api.js` | Прикладной модуль API: валидация фильтров перед отправкой, методы `getTasks`, `getTaskById`, `getCategories`, `loadInitialData` (`Promise.all`). |
| `src/variant.js` | Индивидуальный вариант 3 студента и его параметры фильтрации (`priority: "high"`). |
| `src/main.js` | Клиентский сценарий запуска в Node.js, вывод результатов и демонстрация перехвата ошибки 404. |

## Классификация ошибок

| Сценарий | Ожидаемый `kind` | Фактические поля `ApiError` | Итог |
|---|---|---|---|
| Задача `999` | `http` | `status: 404`, `code: "TASK_NOT_FOUND"` | Успех |
| `completed=yes` | `http` | `status: 400`, `code: "INVALID_QUERY"` | Успех |
| `/debug/error` | `http` | `status: 503`, `code: "SERVICE_UNAVAILABLE"` | Успех |
| `/debug/invalid-json` | `invalid-response` | `cause: SyntaxError` | Успех |
| `/debug/text` | `invalid-response` | `status: 200` (неверный Content-Type) | Успех |
| Не запущен API | `network` | `cause: TypeError (fetch failed)` | Успех |
| Задержка больше тайм-аута | `timeout` | Сообщение о превышении лимита времени | Успех |
| Явный `AbortController.abort()` | `aborted` | Флаг отмены клиентом | Успех |

## Вывод

В ходе практической работы разработана модульная архитектура HTTP-клиента: общий транспортный клиент `createApiClient` изолирован от предметной логики и покрыт модульными тестами с моками, а доменный модуль `createTaskApi` реализует строгую валидацию входных фильтров и схем выходных данных. Освоено параллельное выполнение запросов через `Promise.all`, управление тайм-аутами и отменой через `AbortSignal`, а также структурированная классификация ошибок приложения с сохранением HTTP-статусов и кодов API.
