## 4. Модель данных и функции

Каждая задача представлена объектом со свойствами:
- `id` (число) — уникальный положительный целый идентификатор (`Number.isInteger(id) && id > 0 && id <= Number.MAX_SAFE_INTEGER`).
- `title` (строка) — название задачи от 1 до 100 символов без краевых пробелов.
- `completed` (boolean) — признак выполнения задачи (`true` или `false`).
- `priority` (строка) — приоритет (`"low"`, `"medium"` или `"high"`).

**Назначение файлов:**
- `src/data.js` — неизменяемые исходные массивы (`demoTasks` и `variantTasks`).
- `src/task-service.js` — чистые функции манипуляции массивом задач без сайд-эффектов.
- `src/main.js` — консольный сценарий демонстрации операций.

**Формат результатов операций:**
- Успех создания: `{ ok: true, task: <объект> }`.
- Успех изменения массива: `{ ok: true, tasks: <новый массив> }`.
- Отказ при ошибке валидации или отсутствии: `{ ok: false, error: "Описание причины" }`.

**Ответы на вопросы:**
- **Почему id не равен индексу:** Индекс массива меняется при удалении, сортировке и фильтрации задач. Идентификатор `id` постоянен для сущности на протяжении всего жизненного цикла.
- **Почему getTaskStats возвращает число, а не строку с процентом:** Функция относится к слою бизнес-логики и возвращает чистые числовые данные для дальнейших расчетов. Форматирование в строку (`progress.toFixed(1)`) — задача слоя представления (`main.js` или интерфейса).
- **Какие объекты копируются при изменении задачи:** Создается новый массив, не затронутые задачи сохраняют старые ссылки, а изменяемая задача создается как новый объект через поверхностное копирование с измененным свойством (`{ ...task, completed }`).
